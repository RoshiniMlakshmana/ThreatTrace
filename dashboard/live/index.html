How ThreatTrace Works

Expand architecture overview
Discover → Validate Scope → Security Tools → Normalize Evidence → Correlate Findings → Prioritize → Threat Intel / Hunt / Detection → Purple Recommendation → Human Review

AI may propose/reason (see the AI Assistance card for exactly where, this run) -- it never executes a tool or applies a remediation directly.
Policy + the Security Governor control execution -- every proposal is re-checked by deterministic code before anything real happens, and every real tool call goes through a closed, non-LLM-generated argument vector.
Human approves final outcomes -- a human analyst is the only party who can mark a finding reviewed.

I. Scope & Safety

What this result means -- and what it does not mean
Local development/research interface -- not a production-authenticated control plane. No authentication of any kind is implemented.
Run history is in-memory only for this backend process's lifetime; restarting the backend loses every run.
Security Governor decisions evaluate caller-supplied observable state only -- never proof of intent or authenticated identity.
Detection rule candidates are drafts only: deployment_state is always NOT_DEPLOYED in this checkpoint. Syntax validation is structural only, never detection-efficacy testing.
Human review status shown here is caller-supplied / local development action unless separately authenticated.
Live scanning is localhost-only for Demo Mode -- the backend refuses any non-localhost Bug Bounty target. Authorized External Target mode requires an explicit operator-declared scope and acknowledgment; this is never proof of legal authorization.
